# 第2回 解答

## 演習

* **使ったモデル・設定（result.json の config より）**
  * モデル：`Qwen/Qwen3.5-0.8B`
  * 学習方法：LoRA（量子化なし）
  * パラメータ：`num_train_epochs`: 20 / `lora_r`: 16 / `lora_alpha`: 32 / `lr`: 0.0002 / `seed`: 42
* **自分で学習を実行**
  Google Colab上でモデルの読み込みから、学習前の評価、LoRAによる追加学習、そして学習後の評価まで一通り自分の手で動かしました。
* **学習前後のスコア変化**
  * **学習前：** format_rate 9.5%（2/21） / content_rate 0.0%（0/21）
  * **学習後：** format_rate 100.0%（21/21） / content_rate 90.5%（19/21）
  * フォーマット崩れが完全になくなり、内容の精度も一気に向上しました。
* **退行した質問**
  `regressed` は空配列のままで、学習したことによって逆に答えられなくなった（退行した）質問はぱぅとテストした範囲ではありませんでした。
* **学習後に残った課題（失敗パターン）**
  「手元に根拠がない質問なのに、知ったかぶりをして断定してしまう問題」が残りました。
  具体的には、FAQに載っていない「この講座の最終課題の締切はいつですか？」という質問に対し、学習後も「9月30日23:59です」と架空の日時を具体的に答えてしまい、さらに `needs_review: false`（確認不要）と判定していました。
  JSONの型は完璧に守れていても、根拠のない嘘を堂々と正解っぽく答えてしまう点は解決していません。
* **知識を問う質問（セクション6）の結果と気づき**

| 質問 | 学習前 | 学習後 |
| :--- | :--- | :--- |
| 最終課題の締切 | format_error | asserted（根拠なく断定） |
| 担当教員の名前 | format_error | needs_review（要確認と判断） |
| 次回の講義テーマ | format_error | needs_review（要確認と判断） |
| 課題の提出期限 | format_error | asserted（根拠なく断定） |

  学習前は4問ともフォーマットエラー（出力形式のミス）でしたが、学習後はすべて綺麗なJSONで返せるようになりました。
  ただ、情報がない質問に対して「確認が必要（needs_review）」と正しくガードできたものと、「嘘の情報を断定（asserted）」してしまったもので明暗が分かれました。
* **学習で変わったこと・変わらなかったこと**
  学習後は形式遵守率が 9.5% から 100% へ劇的に改善し、正解率も 0% から 90.5% に跳ね上がりました。
  一方で、根拠がない時に「分からない」と判断する賢さは身につきませんでした。追加学習によって**「回答の“型”を覚え込ませることはできても、情報の正確さや根拠の有無を正しく見極める判断力まで育つわけではない」**ということがよくわかりました。

## 宿題

* **取り組んだレベル：** 基礎
* **変えた設定やデータ**
  学習回数を表す `num_train_epochs` のみを「20」から「10」に半分に減らして再学習しました。
  他の設定（`lr: 0.0002` / `lora_r: 16` / `seed: 42`）は変えず、Colabのセッションを再起動してから最初から走らせ直しました。
* **結果（比較）**

| 評価項目 | 学習前 | 10エポック | 20エポック |
| :--- | :--- | :--- | :--- |
| **format_rate（形式遵守）** | 9.5% | **100.0%** | **100.0%** |
| **content_rate（内容正解）** | 0.0% | **76.2%** | **90.5%** |
| 最終loss | - | 未記録 | 未記録 |
| 学習時間 | - | 未記録 | 未記録 |

  10エポックでも20エポックでも、形式を守る力（format_rate）はどちらも100%と良い数値でした、、何が原因なのか気になる。
  一方で、内容の正解率（content_rate）は20エポックの90.5%に対し、10エポックでは76.2%と、14.3ポイント差が出ました。
  この結果から、**「回答形式の型を習得させるだけなら10エポックでも十分だけど、内容の正確性を上げるには学習回数がしっかり効いてくる」**のかなと考えました。
  （※ただし各1回ずつの検証なので、再現性については何度か試して確かめる必要があります。）
* **計測の制約**
  最終lossと学習時間について、ログを保存しないままColabのセッションを切ってしまい、正確な数字を残せませんでした…。次からは学習結果だけでなく、ログもしっかり保存するように気をつけます！
* **ファインチューニングが「向く場面」と「向かない場面」の考察**
  * **向く場面：**
    JSON形式に揃えたり、指定されたフォーマット・トーンで回答させたりと、**「出力の形や回答パターンを安定させたい時」**にめちゃくちゃ有効だと感じました。
  * **向かない場面：**
    最新情報や、根拠の正確さが命になる場面ではファインチューニングだけだと不安が残ります。
    今回のように、FAQにない情報でも架空の日時を自信満々に断定してしまうリスクがあるため、正確な情報が必要な時は資料検索（RAG）などの仕組みをセットで使う必要があると痛感しました。
* **まとめ**
  今回の実験では、学習回数を半分に減らしてもフォーマットの遵守率はビクともしなかった反面、内容の正解率にはしっかり差が出ました。
  ファインチューニングを行う時は、ただ学習量を増やせばいいというわけではなく、**「型を教えたいのか、知識を深めさせたいのか」という目的に合わせて評価していくことが大切だ**と学びました！
